# Options page and popup with shadcn-svelte

Date: 2026-10-14
Status: approved in conversation, awaiting spec review

## Goal

The options page and the popup still use Harper's `packages/components`
(flowbite-svelte, Svelte 4 event syntax, "honey bronze" colors). They look
hand made. Both pages are rebuilt with stock shadcn-svelte components, and
`packages/components` is deleted. The popup gains a per-tab pause next to the
permanent per-site switch.

Out of scope: the in-page suggestion card and marks (lint-framework). They run
inside foreign pages and cannot use Svelte or Tailwind.

## Decisions

- **Look:** stock shadcn-svelte. No custom style, no mockups.
- **Settings:** every current setting stays (server URL, preferred variants,
  enable on new sites, delay, export enabled domains, activation key,
  apply-suggestion hotkey, user dictionary, disabled rules, clear ignored
  suggestions).
- **Logo:** both pages show `public/logo.svg` (generated by `make icons`).
- **Light and dark mode** follow the system, as now (`src/theme.ts`).

## Setup

- Run the shadcn-svelte CLI in `packages/extension`. Components are copied to
  `packages/extension/src/lib/components/ui/`, utilities to `src/lib/utils.ts`.
- Add the `$lib` alias to `vite.config.ts` and `tsconfig.json`.
- `app.css` becomes the shadcn theme file (Tailwind 4, shadcn CSS variables,
  dark variant on the `.dark` class that `theme.ts` sets). The flowbite import
  and the honey bronze / accent / cream palettes are removed.
- Icons: `@lucide/svelte`.
- Components used: Button, Card, Input, Label, Switch, Select, Textarea, Alert,
  Kbd, Separator.

## Options page (`src/options/Options.svelte`)

- One column, about 640 px wide, centred. Header: logo, "Inkling", version.
- Three Cards, in this order:
  - **Server:** Server URL (Input), Preferred variants (Input),
    "Save and Test" (Button), result as an Alert (default variant on success,
    destructive on failure).
  - **General:** Enable on new sites (Switch), Delay in ms (Input,
    type=number), Export enabled domains (Button), Activation key (Select:
    Double Shift / Double Control / Off), Apply-suggestion hotkey (Kbd showing
    the current keys plus a Button that records a new combination; while
    recording the button reads "Press keys…"), User dictionary (Textarea).
  - **Rules:** Disabled rules (Textarea), Ignored suggestions (Button
    "Clear", shows "Cleared" afterwards).
- Row layout: label and help text left, control right. Textareas sit below
  their label at full width.
- Saving: every setting saves on change, as now. The server settings save only
  through "Save and Test", because `chrome.permissions.request` needs the click
  as a user gesture. The existing `originPattern` validation and messages stay.
- Every control has a `<Label>` so it has an accessible name.

## Popup (`src/popup/`)

Width about 320 px. From top to bottom:

1. **Header:** logo, "Inkling", version.
2. **Site row:**
   - Site name (hostname without `www.`), cut with an ellipsis when too long.
   - **"Check this site"** Switch: the permanent per-site setting, stored as
     today (`setDomainEnabled`).
   - **"Pause in this tab"** Button (Lucide `pause`), shown only while the
     site is on. When paused it reads "Resume in this tab" (Lucide `play`).
   - Status line: "Checking is on" / "Paused in this tab" /
     "Off for this site".
3. **Footer:** ghost Button "Settings" (Lucide `settings-2`) that opens the
   options page.

Special states:

- **No server set:** an Alert "No LanguageTool server is set" with a button
  that opens the settings replaces the site row.
- **Page Inkling cannot check** (no http/https URL, e.g. `chrome://`,
  `about:blank`): Switch and pause button are disabled, and a line reads
  "Inkling cannot check this page".

## Per-tab pause

- Background script keeps the paused tab IDs in `chrome.storage.session`
  (survives a service worker restart, empty after a browser restart).
- New protocol messages: `getTabPaused { tabId }` and
  `setTabPaused { tabId, paused }`, with matching `ProtocolClient` methods.
  The popup gets the tab ID from `chrome.tabs.query({ active: true,
  currentWindow: true })`.
- `shouldLintForRequest` returns false when `sender.tab.id` is paused, before
  any domain check. Requests from iframes in that tab carry the same tab ID and
  are paused too. The content script then receives empty results and its marks
  disappear at the next update.
- The pause ends when the tab closes (`tabs.onRemoved`) or starts loading a
  page (`tabs.onUpdated` with `changeInfo.status === 'loading'`: reload or
  navigation). In-page navigation of single-page apps does not end it.
- Firefox: `storage.session` and both tab events exist in Firefox 115+;
  the manifest's minimum version is checked and raised if needed.

## Removal of `packages/components`

- Delete `packages/components` and the `components` dependency of the
  extension.
- Makefile: drop the `packages/components` build from `deps` and its `dist`
  from `clean`; fix the comment on line 2.
- `packages/extension/scripts/icon.py`: stop writing
  `packages/components/src/lib/logos/Logo.svelte` and
  `packages/components/static/favicon.svg`.
- `pnpm-lock.yaml` is regenerated by `pnpm install`.

## Tests

Playwright, Chromium only (Playwright cannot open the pages of a Firefox
extension), in `packages/extension/tests/`. Locators use role and accessible
name, not CSS classes.

- **Options:**
  - Server URL pointing at the mock LanguageTool server (port 18082) plus
    "Save and Test" shows the success Alert.
  - An invalid URL (`ftp://x`) shows the destructive Alert and saves nothing.
  - Change delay, "Enable on new sites" and the user dictionary, reload the
    page, values are still there.
  - Hotkey: click the record button, press Ctrl+Shift+K, the stored hotkey is
    `Ctrl+Shift+K`.
- **Popup** (opened as `popup.html` in a tab; the active-tab lookup is made
  testable by an optional `?tab=<id>` query parameter used only by tests):
  - Turning the switch off changes the stored domain status.
  - With an empty server URL the "No LanguageTool server is set" Alert shows.
- **Pause:**
  - Two tabs on the same test page with marks. Pause tab A: tab A loses its
    marks, tab B keeps them.
  - Reload tab A: marks come back.

Gates before every commit: `make lint`, `make check`, `make test-unit`,
`make test-chromium`, `make test-firefox`. Screenshots of both pages in light
and dark mode go to the user for review.

`CHANGES.md` gets user-facing entries: new settings page and popup, and the
per-tab pause.

## Order of work

Each step is one commit with green gates.

1. Set up shadcn-svelte in `packages/extension` (alias, theme, components).
2. Rebuild the options page, with its tests.
3. Per-tab pause in the background script and protocol, with tests.
4. Rebuild the popup, with its tests.
5. Delete `packages/components`; update Makefile and `icon.py`.
