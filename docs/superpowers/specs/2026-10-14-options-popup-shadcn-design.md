# Options page and popup with shadcn-svelte

Date: 2026-10-14
Status: approved in conversation, revised after pushback review, awaiting spec review

## Goal

The options page and the popup still use Harper's `packages/components`
(flowbite-svelte, Svelte 4 event syntax, "honey bronze" colors). They look
hand made. Both pages are rebuilt with stock shadcn-svelte components, and
`packages/components` is deleted. The popup gains a per-tab pause next to the
permanent per-site switch, and the per-site switch is fixed for `www.` sites.

Out of scope: the in-page suggestion card and marks (lint-framework). They run
inside foreign pages and cannot use Svelte or Tailwind.

## Decisions

- **Look:** stock shadcn-svelte. No custom style, no mockups.
- **Settings:** every current setting stays (server URL, preferred variants,
  enable on new sites, delay, export enabled domains, activation key,
  apply-suggestion hotkey, user dictionary, disabled rules, clear ignored
  suggestions).
- **Logo:** both pages show `public/logo.svg` (generated by `make icons`).
- **Light and dark mode** follow the system, as now (`src/theme.ts`).
- **No Google Fonts:** the font `<link>`s in `options.html` and `popup.html`
  and the `fonts.googleapis.com` / `fonts.gstatic.com` CSP entries in
  `src/manifest.ts` are removed. The pages use shadcn's default system font
  stack, and opening them no longer contacts Google.

## Setup

- Run the shadcn-svelte CLI in `packages/extension`. Components are copied to
  `packages/extension/src/lib/components/ui/`, utilities to `src/lib/utils.ts`.
- Add the `$lib` alias to `vite.config.ts` and `tsconfig.json`.
- `app.css` becomes the shadcn theme file (Tailwind 4, shadcn CSS variables,
  dark variant on the `.dark` class that `theme.ts` sets). The flowbite import
  and the honey bronze / accent / cream palettes are removed.
- `biome.json` excludes `packages/extension/src/lib/components/ui/`: these are
  vendored CLI files and are not reformatted, so later `shadcn add` updates
  stay clean diffs.
- Icons: `@lucide/svelte`.
- Components used: Button, Card, Input, Label, Switch, Select, Textarea, Alert,
  Kbd, Separator.

## Options page (`src/options/Options.svelte`)

- One column, about 640 px wide, centred. Header: logo, "Inkling", version.
- Three Cards, in this order:
  - **Server:** Server URL (Input), Preferred variants (Input),
    "Save and Test" (Button), result as an Alert (default variant on success,
    destructive on failure).
  - **General:** Enable on new sites (Switch), Delay in ms (Input,
    type=number), Export enabled domains (Button), Activation key (Select:
    Double Shift / Double Control / Off), Apply-suggestion hotkey (Kbd showing
    the current keys plus a Button that records a new combination), User
    dictionary (Textarea).
  - **Rules:** Disabled rules (Textarea), Ignored suggestions (Button
    "Clear", shows "Cleared" afterwards).
- Row layout: label and help text left, control right. Textareas sit below
  their label at full width.
- Saving: every setting saves on change, as now. The server settings save only
  through "Save and Test", because `chrome.permissions.request` needs the click
  as a user gesture. The existing `originPattern` validation and messages stay.
- **Delay:** only a whole number ≥ 0 is saved. An empty or invalid field is not
  saved and shows an error under the field (`aria-invalid` on the Input).
- **Hotkey recording:** while recording, the button reads "Press keys…".
  A combination needs at least one of Ctrl, Shift, Alt (the existing
  `Modifier` type; Meta stays unsupported). Escape cancels and keeps the old
  hotkey. The keydown listener is removed when recording ends in any way
  (saved, cancelled, or the component is destroyed).
- Every control has a `<Label>` so it has an accessible name.

## Popup (`src/popup/`)

Width about 320 px. From top to bottom:

1. **Header:** logo, "Inkling", version.
2. **Site row:**
   - Site name: the hostname shown without `www.`, cut with an ellipsis when
     too long. Only the display drops `www.`; every message to the background
     carries the full hostname (see "Per-site switch").
   - **"Check this site"** Switch: the permanent per-site setting.
   - **"Pause in this tab"** Button (Lucide `pause`), shown only while the
     site is on. When paused it reads "Resume in this tab" (Lucide `play`).
   - Status line: "Checking is on" / "Paused in this tab" /
     "Off for this site".
3. **Footer:** ghost Button "Settings" (Lucide `settings-2`) that opens the
   options page.

Special states:

- **No server set:** an Alert "No LanguageTool server is set" with a button
  that opens the settings replaces the site row.
- **Page Inkling cannot check:** no http/https URL (e.g. `chrome://`,
  `about:blank`), or a host where browsers block content scripts
  (`chromewebstore.google.com`, `chrome.google.com/webstore`,
  `addons.mozilla.org`). Switch and pause button are disabled, and a line
  reads "Inkling cannot check this page".

## Per-site switch (fix)

Today the popup strips `www.` and reads/writes `reddit.com`, while the default
list stores `www.reddit.com` and the background looks up the exact hostname
first (`getDomainLookupCandidates`). On `www.` sites the popup shows the wrong
state and cannot turn the site off.

- The popup sends the full hostname for `getDomainStatus` and
  `setDomainStatus`.
- The background owns all `www.` matching in one pure function
  (hostname → storage keys to read, key to write), covered by a unit test in
  `unit/`. Writing a status for `www.x` or `x` updates the key that the lookup
  will find first, so a read after a write always returns the written value.
- The WordPress/Substack auto-enable in `src/contentScript/index.ts` goes
  through the same path.

## Per-tab pause

- The background stores one key per paused tab in `chrome.storage.session`
  (`paused:<tabId>`), set and removed individually, so concurrent updates
  cannot overwrite each other. `storage.session` survives a service worker
  restart and is empty after a browser restart.
- New protocol messages: `getTabPaused { tabId }` and
  `setTabPaused { tabId, paused }`, with matching `ProtocolClient` methods.
  The popup gets the tab ID from `chrome.tabs.query({ active: true,
  currentWindow: true })`.
- `shouldLintForRequest` returns false when `sender.tab.id` is paused, before
  any domain check. Requests from iframes in that tab carry the same tab ID and
  are paused too.
- The pause ends when:
  - the tab closes (`tabs.onRemoved`);
  - the tab's main frame commits a new document — reload or navigation
    (`webNavigation.onCommitted` with `frameId === 0`). History-API
    navigation of single-page apps (`onHistoryStateUpdated`) does not end it;
  - the user turns the site off in the popup.
- New permission: `webNavigation` (Chrome and Firefox). Check during
  implementation whether it adds an install warning beyond the existing
  `tabs` permission and report it.

## Refresh of open pages

`ProtocolClient.lint` keeps results for 60 s per page and frame
(`src/ProtocolClient.ts`), so a changed setting would show only after up to a
minute. This affects the pause and the site switch.

- After `setTabPaused` or `setDomainStatus`, the background sends a
  `refresh` message to every frame of the affected tab(s)
  (`chrome.tabs.sendMessage`; for a site change, every tab whose URL host
  matches). Errors from tabs without a content script are ignored.
- The content script handles `refresh` by clearing the `ProtocolClient` cache
  and calling `fw.update()`. Marks disappear on pause/off and come back on
  resume/on within one update cycle.

## Tests

Playwright, Chromium only, in `packages/extension/tests/`. Locators use role
and accessible name, not CSS classes.

**Firefox coverage:** Playwright cannot open the pages of a Firefox extension
or reach its background script, so the options page, the popup and the pause
get no Firefox tests. `make test-firefox` keeps covering the in-page marks.

**Test build permission:** the Chromium test build lists the mock server
origin `http://127.0.0.1:18082/*` in `host_permissions` (enabled by an
environment variable, the same way `LT_DEFAULT_SERVER_URL` works). An already
granted origin makes `chrome.permissions.request` resolve `true` without a
browser dialog. Release builds are unchanged.

- **Unit (`unit/`):** the `www.` matching function (read keys and write key
  for `x`, `www.x`, `sub.x`).
- **Options:**
  - Server URL pointing at the mock LanguageTool server plus "Save and Test"
    shows the success Alert.
  - An invalid URL (`ftp://x`) shows the destructive Alert and saves nothing.
  - Change delay, "Enable on new sites" and the user dictionary, reload the
    page, values are still there.
  - An empty delay field shows the error and keeps the stored value.
  - Hotkey: click the record button, press Ctrl+Shift+K, the stored hotkey is
    `Ctrl+Shift+K`. Record again and press Escape: the hotkey is unchanged.
- **Popup** (opened as `popup.html` in a tab; the active-tab lookup is made
  testable by an optional `?tab=<id>` query parameter. Low risk: `popup.html`
  is not web-accessible, so only the extension itself can open it with a
  parameter):
  - Turning the switch off changes the stored domain status.
  - On a `www.` test host the switch shows the correct state and turning it
    off stops checking.
  - With an empty server URL the "No LanguageTool server is set" Alert shows.
- **Pause:**
  - Two tabs on the same test page with marks. Pause tab A: tab A loses its
    marks within a few seconds, tab B keeps them.
  - Resume tab A: marks come back within a few seconds.
  - Pause tab A, then `history.pushState` in tab A: still paused.
  - Pause tab A, reload it: marks come back.

Gates before every commit: `make lint`, `make check`, `make test-unit`,
`make test-chromium`, `make test-firefox`. Screenshots of both pages in light
and dark mode go to the user for review.

`CHANGES.md` gets user-facing entries: new settings page and popup, the
per-tab pause, the site switch now working on `www.` sites and taking effect
immediately, and the pages no longer loading Google Fonts.
